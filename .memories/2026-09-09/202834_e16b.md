## Migrated from Cloudflare Pages to Workers + Static Assets

The `cloudflare` plugin skill states plainly: Workers + Static Assets is the recommendation for **all new** projects; Pages Functions is for maintaining _existing_ deployments. Caught at the cheapest possible moment — `functions/` held only a tsconfig, no Function had been written yet.

### Changes

- `wrangler.toml` → **`wrangler.jsonc`** with `main`, `assets.not_found_handling: "single-page-application"`, `assets.binding: "ASSETS"`, `assets.run_worker_first: ["/api/*"]`
- **`src/worker/index.ts`** — single Worker entry with an `/api` router (returns typed JSON 404 until Phase 2). No file-based routing; Pages Functions had that, Workers doesn't.
- Deleted `public/_routes.json`, `functions/`, `wrangler.toml`
- Added **`@cloudflare/vite-plugin`** (1.54.6; peers vite ^6.1 ✓ 6.4.3, wrangler ^4.130 ✓ 4.130.0)
- **`tsconfig.worker.json`** for the Worker; `tsconfig.app.json` now **excludes `src/worker/**`** — without that exclusion the app project fails on `Fetcher`/`ExportedHandler`
- Scripts: dropped `dev:cf` and `pages:dev`; `dev`=vite, `preview`, `deploy`=build && wrangler deploy; typecheck points at tsconfig.worker.json
- CLAUDE.md, README, ci.yml comment all de-Pages'd

### Three problems this solved for free

1. **Deep links.** `not_found_handling: single-page-application` replaces the `public/_redirects` file we were missing — `/quests`, `/stats`, `/about` would have 404'd on cold load, which is exactly how a home-screen PWA launches.
2. **`_routes.json` indirection** → one `run_worker_first` field.
3. **The `dev:cf` wart.** `npm run dev` now runs the Worker in workerd alongside HMR. Verified: `/api/hiscores` → our JSON 404 from the Worker, `/about` → 200 SPA shell. No proxy, no 502-on-first-request.

### Gotcha worth remembering

**Never set `assets.directory` in `wrangler.jsonc`.** The Vite plugin generates `dist/stagescape/wrangler.json` at build time and populates that field itself (`"directory": "../client"`). Build output splits: `dist/client` (assets, sw.js, 24 precache entries) and `dist/stagescape` (Worker).

### Deploy path changed

Workers Builds (git-connected) rather than the Pages git integration. gotorecipe **stays on Pages** — don't copy this shape backwards into it.

Repo is live at github.com/dylanclaywell/stagescape; all three earlier commits pushed, `main` tracks `origin/main`.
