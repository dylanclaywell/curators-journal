## Founding premise invalidated: side-by-side docking is impossible on iPad

Measured on device, not theorised. The whole "docked rail beside the game in Stage Manager" concept **cannot work**:

- **Safari minimum width: 375px.** Installed PWA: also 375px — browser chrome wasn't the constraint.
- **Minimum window _height_ is larger still**, which kills the short-and-wide "sit in OSRS's letterbox band" idea.
- **OSRS only offers two sizes** — fullscreen and slightly smaller. It doesn't resize freely, so there's no 2/3 tile for Split View and no arrangement that frees up space.

Net effect: OSRS + a 375px window exceeds the screen, so Stage Manager overlaps them. User gets OSRS's letterbox gap _and_ StageScape covering game content. Swapping works fine; it just looks bad.

### Consequence — the design target flips

Primary case is no longer a 375px rail. It's **full-screen (or near), degrading down to 375px as the floor.** The app is swapped to, not glanced at continuously.

### What this makes important (new requirements)

1. **UI state restoration across swaps** — iOS suspends/kills backgrounded PWAs. Active panel, scroll position, current quest and step must all survive. If swapping back resets to the top of the queue, the swap cost multiplies. This is now a first-class requirement, not polish.
2. **No spinner on resume** — serve cached hiscores instantly, revalidate quietly.
3. **Re-orientation under one second** — next actionable step pinned large at top.
4. **Room to show more** — at full screen we can show quest step + requirements + stats together, which was impossible in a rail.

### What survives

None of the narrow work was wasted, and container queries turned out to be a better call than we knew — one codebase now has to serve both a 375px overlap window and a full-screen layout. The three-stage tab degradation and the 44px touch floor all still apply at the floor case.

### Live alternative worth considering

**A second device.** The 375px layout is literally an iPhone viewport — we have accidentally already built the ideal iPhone app. Running StageScape on a phone beside the iPad gives genuine always-visible with zero overlap.

### Action pending

CLAUDE.md's "What this is" section still claims "runs in Stage Manager beside the game, narrow and always visible" — actively misleading now and needs rewriting, or a future session will optimise for a use case that doesn't exist.
