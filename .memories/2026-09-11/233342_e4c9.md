## Phase 4 session: items, prerequisite chain, the queue panel, and a workflow rethink

Nine commits on `main` (`6864dfa`..`415c056`), **none pushed** — the user always pushes.

### Slices closed
- **4d′ items required.** `items`/`recommended` were never scoped into the dataset. `QuestItemLine {text, heading?, depth?}` rather than the planned bare `string[]`, because Heroes' Quest splits items under "If you are a Black Arm Gang member:" / "Phoenix Gang member:" — flattening asks for both sets. Headings detected by trailing colon (15 of 16, zero false positives; wholly-bold looked better and wasn't).
- **4d″ prerequisite chain.** `prerequisiteChain(id, index)`, separate from `buildPlan` because that one *also* prunes satisfied branches, so a chain would shrink as you complete it. Takes no `PlayerState`, so it structurally cannot filter by progress.
- **4e the queue panel.** Next up over tabbed Plan/Goals, start/finish inline.

### The workflow rethink (user-driven, and the best call of the session)
The user spotted that the Queue's "Add another" *"feels like I'm doing one single action, when really you can do any number of actions"* — a mode change wearing the costume of a button. Result: curating is now a Quests-panel activity end to end (goal toggle added to quest detail), and the Queue has **no add affordance** except in the empty state, where the link names a destination ("Browse quests") rather than promising an action.

They also proposed tabs-within-the-panel for plan vs goals, reframing them as *different workflows* — better than either option I'd offered.

### Engine change worth knowing about
`buildPlan` sorted goal ids before walking them, so **arranging goals had no effect on the plan at all**. Now walks the caller's order. Measured: swapping two goals moves Song of the Elves from step 43 to 14, same 44 steps, dependency order intact.

### Two traps that cost real time
1. **Template literals ate regex escapes, twice.** `` `\s` `` in a template literal is the character "s". The level matcher compiled fine and matched *nothing* — the feature looked like it worked and simply never coloured anything. Caught only by checking in the browser. Both now use `String.raw`.
2. **`.pressable` is oak-only.** It hard-codes brown hover/active, so a parchment control flashes brown under the thumb. Added `.pressable-parchment`; documented in CLAUDE.md.

### Design calls recorded
- Amber, not red, for unmet *recommendations* and blocked plan steps — red is "blocked", and nothing in those lists blocks anything.
- Selected = dark oak + gold everywhere (user corrected an inversion I shipped).
- Long lists collapse with "Show all N" — 35 oak rows buries everything under it.
