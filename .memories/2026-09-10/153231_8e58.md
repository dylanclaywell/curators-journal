## Skill icons: evaluated, then switched to Jagex's own

`71dc1f3` responsive grid, `1d10147` skill icons.

### The A/B that settled it

Built the grid with real game-icons artwork (not stand-ins) and compared at identical framing. Result: **~8 of 24 read at 15px, the rest were mush** — Strength a blob, Magic/Runecraft/Herblore indistinguishable circles, Fishing's rod sub-pixel. And the ones that _did_ read were the ones needing help least ("Cooking" is legible as a word). Cost: StatsView 6.24 → 38.29 kB raw (2.45 → 18.01 gzip).

Root cause: game-icons are drawn on a 512 grid **for large display**. Jagex's are 23–25px, **drawn small by design** for a cramped in-game interface — which is why switching fixed recognition _and_ legibility at once. 24 icons total **5.2 KB**, and StatsView went back to 6.52 kB.

### Two premises I had to correct mid-conversation

- **Workers have no filesystem.** User asked about saving icons to it; they're V8 isolates. Durable options are R2 or KV, both needing bindings.
- **Images need no proxy.** CORS only constrains `fetch()`; `<img src>` renders cross-origin freely. So the Worker was never required here — which opened up better options than proxying.

### Chosen approach: build-time fetch, gitignored

`scripts/fetch-skill-icons.mjs` resolves canonical URLs via the wiki's `api.php` (the wiki appends cache-busting queries, so guessing paths is fragile), downloads to `public/skill-icons/`, runs as part of `npm run build`. Gitignored — **repo redistributes no Jagex assets** (verified: 0 icon files in the commit). Precache 24 → 48 entries, so offline works on first launch. Fails soft on wiki outage; UI hides missing icons via an `@error` handler.

Rejected runtime proxying: 8 KB of never-changing art doesn't justify a Worker route, and a new skill needs a `SKILL_NAMES` change anyway so the rebuild happens regardless.

### Rendering detail

`image-rendering: pixelated` — they're pixel art and smooth downscaling ruins them. Rendered at 20px against ~25px native.

### Licensing — full reasoning now in NOTICE.md (in-repo, don't duplicate here)

Key fact found by checking the wiki file page rather than assuming: it states the art is Jagex copyright "used with permission" — **that permission is the wiki's and does not transfer**. Downloadability ≠ rights. The Fan Content Policy has a genuine gap on static assets in third-party apps. Decision made knowingly; NOTICE.md records the three constraints that must hold (never commit assets, stay non-commercial, don't add more Jagex assets casually).

### Still outstanding

**No `LICENSE` file for our own code.** NOTICE.md is explicitly scoped to third-party material, so it reads correctly, but the project's own terms are unstated.
