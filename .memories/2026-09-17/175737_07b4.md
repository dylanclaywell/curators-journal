WikiSync API ruled out; achievement diary dataset source confirmed as the wiki

**Decision: `sync.runescape.wiki` is off limits.** While scoping achievement
diaries I found WikiSync serves diary tiers, quest states, levels and combat
achievements as public JSON by username (verified live — `GET
/runelite/player/Zezima/STANDARD` returns `achievement_diaries` nested region →
tier → `{complete, tasks[]}`). It looks like it makes Phase 5's plugin
unnecessary. It doesn't: RuneScape:WikiSync §Third-party use asks third parties
not to use it — players consented to sharing with *the wiki*, not arbitrary
sites — and says they will actively limit outside callers. Consent-scoped, so
nothing to negotiate or wait out. Dead end on etiquette and on reliability.

Recorded in CLAUDE.md beside the third-party source table (it will look like the
answer again) and in ROADMAP.md's "Rejected, with reasons worth keeping" under
Phase 5. Kept one thing from it: its payload shape (quests as enum, diaries
nested region → tier → tasks) corroborates the wire format's "not a bare
top-level map" argument — arrive at that independently, don't copy theirs.

**Diary requirements: no API, same wiki pipeline as quests.** Cargo/SMW still
absent; no `Module:Diary/data` equivalent (only a user sandbox calculator). But
per-page templates are better structured than the quest ones:

- Inventory: `embeddedin=Template:Infobox Achievement Diary`, ns=0 → 13 pages =
  11 classic diaries + Kourend & Kebos + one false positive (`Steam
  Achievements`) to filter.
- Per-tier skill reqs: `{{DiarySkillStats |Thieving = 38 |Crafting = 49 |Quest =
  20 |Total = 391 |boostable=true}}` — near-direct reduction to
  `SkillRequirement[]`.
- Quest prereqs: adjacent tables with machine-readable `data-rowid="Underground
  Pass"` per row — cleaner than the quest pages' prose was.
- Task tables carry `data-diary-name` / `data-diary-tier`.

Three wrinkles: `|Quest = N` is quest *points*, not a skill, needs its own
field; "Additional requirements" tables hold partial states ("Started Sea Slug",
"Partial completion of Watchtower") that binary todo/doing/done can't express;
ironman `<ref>` notes are the same deferred problem quests already have.

Confirmed separately: hiscores `index_lite.json` has 91 activities and zero
diaries, so ROADMAP's ranking holds — diaries are a dataset problem, not an
engine problem.

Not started: the `build:diaries` generator. Needed either way.
